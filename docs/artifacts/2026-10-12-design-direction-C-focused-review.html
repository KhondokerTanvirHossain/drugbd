C Design direction

Focused Review

One record, one decision, full attention. A quiet editorial identity on the outside; on the inside, a keyboard-first workspace where pharmacists confirm each medicine before anyone else can see it.

1

Name and wordmark

A Bangla word, short enough to say across a pharmacy counter, with a meaning that matches how the data is made: one verified unit at a time.

2

Principles

Seven rules every screen in this direction is checked against. Each one names the Apple HIG and Material 3 ideas it borrows from.

One record holds the stage

The reviewer sees one medicine at a time, titled large, with no list competing for attention. Context such as batch and progress sits at the edge.

ClarityDeferenceHierarchy

Absence is never safety

Missing data gets its own visual form, a hatched surface, and its own sentence. It never borrows green or the word “none”.

ResponsibilityColor rolesCommunicating state

Evidence on request

Summary first, proof one keystroke deeper. Stage checks are one line each; source text, all pairs and raw codes open with E.

SimplicityProgressive disclosureContainment

Source beside result

The DGDA register and the extracted data line up row by row, so a mismatch is something you see, not something you search for.

Grouping and mappingHarmonyConsistency

Hands stay on the keys

J and K move, O approves, I reports, E expands. Every key has a visible button twin and a hint, so the mouse never becomes a requirement or a trap.

FlexibilityFamiliarityAdaptive

Calm progress, clear exceptions

Progress is a thin ribbon that never pulses or counts down. Warnings and failures take colour, shape and words at once.

FeedbackTonal surfacesState layers

Every state has a way out

Each error says what happened, what was kept and the one action that fixes it. Decisions can be undone for 8 seconds.

A

A ribbon, not a percentage

Ten segments for ten records. Approved records turn green, reported ones turn red, and the current one is outlined. Nothing pulses or counts down, so speed is never the goal.

B

Checks before content

The four pipeline stages sit in one row with icon, word and note. A warning gets a tinted top edge and its note. It doesn't block the decision, it tells the reviewer where to look.

C

Aligned comparison

Source on the left, result on the right, with a match mark between them. The extracted column is tinted with the accent so it's always clear which side is the machine's.

D

Same safety words as the public

The reviewer sees the same labels doctors will see, so they review the actual wording, including “Severity not classified by DDInter”.

E

Decision dock

Glass bar pinned to the bottom with the primary action on the right, as in macOS dialogs. It states the effect of OK for the current role. For an engineer it reads: “Your OK is recorded. Only a pharmacist's OK publishes.”

F

Report issue opens in place

The note field grows up out of the dock, so the record stays in view while you write. The counter and the 5-character minimum are shown before you submit, not after.

Dotted values are layout placeholders. Only the values listed in the product brief are real; the live screen shows register and pipeline values in these places.

One brand, more than one active substance. Each one is mapped and checked separately.
